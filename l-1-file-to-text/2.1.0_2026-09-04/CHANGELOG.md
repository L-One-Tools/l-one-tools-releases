# CHANGELOG

## L-1 File To Text v2.1.0 公开内测版 — 2026-09-04

- 更新公开内测资料：README、模型说明和隐私说明改为反映当前 FireRed 本地候选路线，不再沿用 Whisper、自动英中翻译或资源中心下载的旧说法。
- 恢复首次配置闭环：资源中心显示本机硬件建议、来源、许可证、大小和下载前确认；FireRed 中文模型按固定修订逐文件校验 SHA-256，FFmpeg 作为单独 GPL 资源按压缩包 SHA-256 校验后安装到用户资源目录。
- 移除真实运行对开发机 `E:` 模型目录的依赖；Worker 按用户选择的资源目录加载模型和 FFmpeg。
- 清理 FireRed 输出中的 `<sil>` / `<silence>` 解码标记；英文内容不再仅因连续英文行被当作歌词拒收。
- 中文内容中夹有长英文片段时，任务记录提示人工复核，正文不自动删除。当前没有已验收的本地语义审核模型，因此不声称可以自动区分歌词、台词和引语。
- 本候选仍不提供中文翻译稿或 `.srt` / `.vtt` 中文字幕输出；大批量真实文件测试仍在进行。

## 2.0.9-candidate.11 — 2026-08-31

- 中文知识库快速输出改为双文件：`.zh.raw` 保留原始转写，`.zh.kb` 生成离线简体与基础检索排版副本；规范稿不会伪造或更正识别到的词。
- 增加 OpenCC 的本地繁转简组件，并将其 Apache-2.0 许可证纳入候选包 SBOM 证据路径。
- 对同一份 138.81 秒中文测试视频完成 SenseVoice-Small 离线基准：42.43 秒但仅输出 465 字且漏字严重，未替换当前 Whisper Medium 中文路线。

## 2.0.9-candidate.10 — 2026-08-31

- 默认界面移除内容语言、语音识别模型和语义模型选择，用户只选择处理目标；模型选择不再成为误用来源。
- 队列逐文件以本地 25 秒语音预检决定路线：中文改用 Whisper Medium 并跳过英中翻译；英文使用 Whisper Small 与本地 OPUS-MT；有效语音很少或语言不确定时使用稳健多语种识别且不臆造翻译。
- 每个任务将路线、依据、预检时长和实际执行引擎写入本地运行记录，混合语言批次不再继承前一个文件的语言选择。

## 2.0.9-candidate.9 — 2026-08-31

- 修复队列状态同步：常驻工作进程的明确完成信号会立即结算当前文件；结果文件仍作为终态兜底。
- 结果文件检查提前到事件流解析之前，避免末尾事件记录未完整写入时把已完成任务遗留为“处理中”。
- “知识库快速”界面正确显示实际使用的 Whisper Small。

## 2.0.9-candidate.8 — 2026-08-31

- 新增默认“知识库快速”通道：英文视频先以 Whisper Small 本地识别，再以 OPUS-MT 英中模型进行本地 CPU 快速翻译；不调用云端，也不再把普通双语任务交给 Qwen 7B。
- 英文原稿与中文快速稿分开输出为 `.en.txt/.en.md` 和 `.zh.quick.txt/.zh.quick.md`，原稿不会被翻译或整理覆盖。
- 新增受管资源 `OPUS-MT English → Chinese`，仅下载约 315 MB 的运行必需文件；Qwen 仍保留给用户明确选择的高质量语义整理。
- 修复 Whisper Small 批处理路径在未内置 VAD 资源时会以“未找到音频片段时间戳”中断普通视频的问题，知识库快速通道改用稳定的单路 CPU 解码。
- 7 分 10 秒英文基准视频端到端实测为 119.21 秒（27.7%）：识别 89.20 秒，快速翻译 29.90 秒，满足“总时长不超过源文件 30%”的当前基准目标。

## 2.0.9-candidate.7 — 2026-08-31

- 撤回运行时不完整的 candidate.6 安装包。该候选包的 PyInstaller 主程序未完成收集，缺少 `_internal/python312.dll`，不得使用或分发。candidate.7 强制从空白构建目录完整生成主程序和隔离 Worker Runtime，并以实际安装后启动作为门禁。

## 2.0.9-candidate.6 — 2026-08-31

- 将当前队列的开始、暂停、继续和重新执行收敛为单一主按钮；活动队列右下仅保留与真实可恢复状态匹配的批量操作。正常运行时显示不可点击的灰色“任务运行正常”，暂停时显示“全部继续”，失败或异常中断时显示 Pantone 1805 C 近似色的“全部重新执行”。
- 工作进程仍持续 heartbeat 时不再弹出“任务长时间没有推进”的模态窗口；该情况仅写入可核查活动记录。只有已确认工作进程失联并停止时才弹出阻断性失败提示。
- 标准模式 Whisper Medium 改为单路确定性解码并明确使用至多六个物理 CPU 核心；高精度模式保留较慢的多候选解码。
- 双语导出在未启用 AI 整理时固定走 Qwen2.5 翻译路径，MiniCPM 保留给显式 AI 整理实验；翻译文本分段从 1100 字符提高至 2200 字符，减少长文本的本地模型往返次数。

## 2.0.9-candidate.5 — 2026-08-30

- 预留蓝色更新入口；只有客户端已验签确认有较新正式版时才显示，未配置可信更新渠道时不轮询、不显示、不下载。

- 新增安装包字节数与 SHA-256 完整性验证，以及仅在受控发布机使用的签名清单生成脚本。
- 新增腾讯 COS + EdgeOne 的正式分发运维规范；现有轻量服务器不作为长期安装包主分发源。

## 2.0.9-candidate.4 — 2026-08-30

- 新增全阶段 Worker heartbeat；界面可区分“工作进程仍存活但业务进度停滞”和“工作进程已经失联”。
- 工作进程 45 秒没有 heartbeat 时立即预警；持续 600 秒失联时停止该进程并把可核查原因及诊断目录写入任务记录，避免无限等待。
- 工作进程仍回应但业务进度 300 秒没有变化时给出慢任务预警，允许用户继续等待或安全暂停。
- 检测界面监控长时间未运行的空窗；电脑休眠、休眠恢复或系统冻结后先恢复监控并重新给予宽限期，避免唤醒后误判失败。
- 本地语言模型单个文本块增加 600 秒外层硬超时；超时后停止对应 llama.cpp 服务或进程。
- 翻译、AI 整理或完整性检查失败时保留已锁定原文和已写出文件，同时将任务明确标为失败并开放“查看”和“重新识别”。
- 软件重新启动时，遗留运行任务记录最后阶段和最后活动时间；不再把无法证明的休眠、崩溃或用户关闭猜测成唯一原因。
- 构建阶段强制清除第一方 `__pycache__` 和 `.pyc`，避免把开发机字节码缓存或其它 CPython 小版本缓存带入 Worker Runtime。
- installer-only 公开资料采用明确白名单，不再混入旧版本验证记录。
- 修复首次启动向导响应系统主题变化时可能递归刷新样式、导致冻结版在 `Qt6Gui.dll` 栈溢出的启动崩溃。

本候选需完成独立安装、正常窗口启动、真实超时/停滞场景、卸载和恶意文件扫描验证后，方可晋升正式版。

仍有限制：视频输入依赖用户系统提供 FFmpeg；GPU 加速未包含在本 CPU 候选；模型需由用户主动下载；可选本地翻译模型在低配置 CPU 上可能很慢。
